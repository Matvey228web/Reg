# Карта проекта

`README.md` говорит, из каких четырёх частей система состоит. README внутри
каждой папки — как эта часть работает. Здесь третье, чего нет ни там, ни там:
**что лежит в каком файле**, чтобы аналог находился поиском по этой странице, а
не чтением всего подряд (первое правило из [`CLAUDE.md`](../CLAUDE.md)).

Сделано как таблица папок в `README.md` — тот же разбор, на уровень глубже.

## Четыре слоя

```
 site/  ──── заявка текстом ───▶  app/  ───▶  worker/  ───▶  apps-script/  ───▶  Google Sheets
   │                                │           (кэш)         (вся логика)       (истина)
   └── витрина ── catalog.json ─────┘
```

Истина — в таблице. Всё остальное — способы в неё смотреть и писать.
`worker/` стоит перед таблицей и ничего не хранит: кэш живёт пять минут и
сбрасывается на любой записи. Публичные чтения для сайта (каталог, объявления)
имеют ещё долгую копию на неделю: таблица отвечает до 30 секунд, и без неё первый
посетитель после сброса не увидел бы объявлений (сайт ждёт пять секунд).

Ни один слой не знает про соседа больше, чем адрес: у `app/` это
`WEBHOOK_BASE_URL` в `app/js/config.js`, у `site/` — `BACKEND` в
`site/common.js`, у Worker — `UPSTREAM_URL` в `worker/wrangler.toml`. Все три
сейчас указывают на Worker, кроме `UPSTREAM_URL` — он на таблицу. Убрать Worker
из цепочки — значит подставить в первые два адрес таблицы; больше нигде править
не нужно.

## apps-script — бэкенд

| Файл | Что это |
|---|---|
| `Code.gs` | бэкенд целиком: схема таблицы, роутер, все ручки, импорт, бот |
| `deploy.js` | выкладка через Apps Script API, без вставки руками |
| `test-local.js` | прогон логики на эмуляторе таблицы, без Google-аккаунта |
| `act-template.html` | бланк «Акт приема-передачи материальных ценностей №…-МТО», шаблон для печати |

### Что внутри `Code.gs`

Файл один намеренно: ручки лежат рядом, и новая видна на фоне соседних. Внутри
он разделён комментариями-линейками — ищите по названию раздела, а не по номеру
строки.

| Раздел | Что там | Точка входа |
|---|---|---|
| Схема | список вкладок и колонок, текстовые колонки, коды категорий | `SHEETS`, `SCHEMA`, `TEXT_COLUMNS`, `CATEGORY_CODES` |
| Первоначальная настройка | создаёт вкладки с заголовками, запускается один раз кнопкой «Run» | `setupSheets`, `setupEverything`, `seedSheet` |
| Разовый импорт | чужая выгрузка инвентаризации → каталог и справочник моделей | `importInventory`, `reimportInventory` |
| Архив журнала | выгрузка выдач в файл и подрезка листа | `archiveJournal`, `trimJournal` |
| Ночное обслуживание | копия таблицы на Диск и подрезка `Logs`; триггер ставится руками один раз | `dailyMaintenance`, `dailyBackup`, `trimLogs`, `setupTriggers` |
| Уборка тестовых строк | запуск из редактора: просмотр, затем копия таблицы и удаление пробных заказов с выдачами, учеников, сотрудников | `cleanupTestDataPreview`, `cleanupTestData` |
| Точка входа | приём POST, разбор токена, `case` на каждую ручку | `doPost`, `doGet` |
| Хендлеры | по одной функции `handle*` на ручку | см. таблицу ручек ниже |
| Заказы | разбор сообщения с сайта, студенты, состав заказа | `parseOrderMessage`, `normalizePhone` |
| Телеграм-бот | в чат склада только заявки (тема «ЗАЯВКИ») и акты (тема «АКТЫ»); откат в General, если тема не приняла | `tgSend`, `notifyThreadId`; `notifyRefusal` — одно место, где сказано, почему отказ |
| Инвентаризация | журнал сверок; каталог сверка не меняет | `handleInventorySave` |
| Настройки | значения из листа `Meta`, категории, обслуживание | `SETTINGS_SPEC`, `getSettings` |
| Занятость по датам | на чём стоит бронь: какие заказы держат технику | — |
| Общие хелперы | даты, деньги, доступ по роли, журнал сбоев | `logEvent` — запись в `Logs` |

Служебное — ошибки сервера, отказы Telegram, несобравшийся акт, неудачная
ночная копия — в чат не идёт никогда: `logEvent` пишет его в лист `Logs`.

Ночное обслуживание: `setupTriggers` (запускается из редактора, как
`setupSheets`) ставит один ежедневный триггер `dailyMaintenance` около 3:00 и
снимает прежние. `dailyMaintenance` зовёт `dailyBackup` — копия таблицы в папку
Диска «Mifs Rent — копии», хранится 14 — и `trimLogs` — строки `Logs` старше
90 дней. Каждый шаг в своём `try`, неудача — строкой в `Logs`.

Токен бота (`TELEGRAM_BOT_TOKEN`) живёт в двух серверных хранилищах — Script
Properties (таблица) и Worker Secrets (вебхук). В репозиторий и в браузер он не
попадает.

### Вкладки таблицы

| Вкладка | Что в ней |

| `Categories` | справочник категорий: код, две цифры номера, учёт количеством |
| `Staff` | сотрудники: логин, хэш PIN, роль, токен сессии, блокировки |
| `Students` | арендаторы, опознаются по телефону |
| `Orders` | заказы с сайта: даты, представитель несовершеннолетнего, ссылка на акт |
| `OrderItems` | состав заказа строками: модель, количество, сколько выдано |
| `Transactions` | журнал выдач и приёмов |
| `Defects` | дефекты и их закрытие |
| `Inventory` | журнал сверок: итог и расхождения, не все найденные позиции |
| `Announcements` | объявления склада для сайта: заголовок, абзацы, «показывать до»; снятое получает `removed_at`, а не удаляется |
| `ImportMap`, `ImportRules` | как читать чужую выгрузку: синонимы колонок и раскладка по категориям |
| `Meta` | значения настроек |
| `Logs` | журнал сбоев: время, род, ручка, причина, текст, подробности. Подрезается до 90 дней ночью |
| `Clients` | прежняя модель «клиент/проект». Оставлена: на неё ссылаются старые строки журнала |

### Ручки

Все — POST на один адрес, путь в теле запроса. Группы, а не полный список; сам
список — в `doPost`.

| Группа | Ручки |
|---|---|
| Вход и сотрудники | `/auth/login`, `/staff/*` |
| Каталог и вещи | `/item/*` (правка карточки — `/item/update`, номера — `/item/numbers`), `/equipment/list`, `/model*` |
| Выдача и приём | `/transaction/checkout`, `/transaction/checkin`, `/transaction/checkin-batch` (приём всего заказа одним запросом) |
| Дефекты | `/defect/report`, `/defect/resolve`, `/defects/list` |
| Заказы | `/order/*`, `/orders/list`, `/students/list`, `/student/history` |
| Сайт | `/public/catalog`, `/public/order`, `/public/announcements` |
| Объявления | `/announcements/list`, `/announcement/save`, `/announcement/remove` (любой вошедший, не только Admin) |
| Акт | `/act/template`, `/act/build` |
| Бот | `/notify/*`; `/labels/send` выведена из работы и отвечает `410` с подсказкой — ради старых версий приложения |
| Сверка | `/inventory/save`, `/inventory/list` |
| Админка | `/settings/*`, `/category/*`, `/maintenance` |

## app — склад

Один `index.html` со всеми экранами, переключает их `router.js`. Сборки нет:
файлы выкладываются как есть, поэтому **порядок тегов `<script>` в
`index.html` — это и есть порядок загрузки**, а `?v=` у своих файлов
поднимается вместе с любой правкой `app/js/*` — Telegram держит файлы в кэше.

### Каркас

| Файл | Что это |
|---|---|
| `index.html` | все экраны разметкой + подключение скриптов |
| `js/app.js` | точка входа: инициализация SDK, регистрация экранов, выбор стартового |
| `js/router.js` | показ и скрытие экранов, `Router.register(name, { onShow })` |
| `js/config.js` | адрес бэкенда, демо-режим, срок сессии, запасной справочник категорий |
| `css/style.css` | вся вёрстка |
| `_headers` | заголовки Cloudflare Pages |

### Данные и транспорт

| Файл | Что это |
|---|---|
| `js/api.js` | `apiPost(endpoint, body)` — единственный способ обратиться к бэкенду |
| `js/cache.js` | кэш списков в localStorage, пять минут — как и в KV у Worker |
| `js/mock-data.js` | ответы демо-режима (`MOCK_MODE: true`), по ветке на ручку |

### Обёртки платформы

| Файл | Что это |
|---|---|
| `js/telegram.js` | `TG` — обёртка над Telegram WebApp SDK, мягко деградирует вне Telegram |
| `js/qr.js` | `QR` — рисование кода на canvas и вызов нативного сканера |
| `js/vendor/qrcode-generator.js` | сторонняя библиотека генерации QR |

### Общее по экранам

| Файл | Что это |
|---|---|
| `js/util.js` | `escapeHtml`, `isTyping` и прочая мелочь на несколько экранов |
| `js/suggest.js` | подсказки в строках поиска |
| `js/fab.js` | круглая кнопка главного действия в углу |
| `js/pull.js` | «потянуть для обновления»; ставится только там, где клиент умеет отключить свой свайп |
| `js/swipe.js` | свайп по строке. **Не подключён** и не используется — оставлен рабочим под будущие списки |

### Экраны

| Файл | Экран |
|---|---|
| `js/auth.js` | вход по PIN, сессия в localStorage |
| `js/pin.js` | смена своего PIN, доступна любой роли |
| `js/catalog.js` | каталог: фильтры, поиск, добавление вещи с QR |
| `js/item.js` | карточка вещи: статус, история выдач и дефектов |
| `js/scan.js` | скан QR → выдача, приём или дефект по текущему статусу |
| `js/orders.js` | журнал заказов с сайта, ввод вставкой сообщения бота |
| `js/order.js` | карточка заказа, выдача прямо из неё |
| `js/repair.js` | доска дефектов с фильтром по статусу |
| `js/inventory.js` | сверка склада сканированием, по кэшу, один запрос в конце |
| `js/announcements.js` | объявления склада: список, добавить, править, снять; видят все вошедшие |
| `js/labels.js` | печать QR на термопринтер этикеток |
| `js/staff.js` | сотрудники и роли (администратор) |
| `js/models.js` | справочник моделей по категориям, перенос с перенумерацией |
| `js/settings.js` | настройки: `FIELDS` — список полей, секции `data-panel` — подразделы |

Настройка системы живёт в двух местах сразу: `SETTINGS_SPEC` в `Code.gs`
(значение и подсказка) и `FIELDS` в `settings.js` (поле на экране). Так
устроены и темы форума: `notify_chat_id` — чат склада, `notify_thread_orders`
и `notify_thread_acts` — номера тем для заявок и актов (раздел «Адреса и
связи»; пусто — General).

## site — публичный сайт

Отдельный проект Pages: свой адрес, свои правила кэша, своя выкладка. Сайт
**не пишет в таблицу** — он собирает текст заявки, который разбирает
`parseOrderMessage` в `Code.gs`.

| Файл | Что это |
|---|---|
| `index.html` + `app.js` | витрина: разделы, решётка карточек, поиск, фильтр |
| `item.html` + `item.js` | страница позиции; наличие спрашиваем только при выбранных датах |
| `cart.html` + `cart.js` | заявка: состав, даты, данные студента, текст для склада |
| `common.js` | `Site` — снимок каталога, корзина, помощники; общее для всех страниц |
| `style.css` | вся вёрстка сайта |
| `theme.js` | тема (тёмная/светлая) и сезон по календарю; ставит `data-theme`/`data-season` на `<html>` до отрисовки |
| `themes/` | сезонные темы: `<id>.css` (токены + декор) и `art/` |
| `announcements.json` | запасные объявления склада, когда публичная ручка не ответила |
| `catalog.json` | снимок каталога, лежит статикой. Генерируется, руками не правится |
| `build-catalog.js` | сборка этого снимка |
| `photos.py` | единая вёрстка фотографий каталога: квадрат 800×800 |
| `_headers` | заголовки Cloudflare Pages |

Почему снимок, а не запрос: Apps Script отвечает 5–8 секунд, и витрина, которая
столько думает, — не витрина.

## worker — кэш перед таблицей

Включён и работает; через него ходят и склад, и сайт.

| Файл | Что это |
|---|---|
| `src/index.js` | Worker целиком: список кэшируемых чтений, TTL, добор незаехавших заявок, вебхук бота (`/id` отвечает и номером темы), `GET /health` — сколько заявок в очереди и в `dead:` |
| `wrangler.toml` | адрес таблицы (`UPSTREAM_URL`), выключатель кэша, крон раз в пять минут |
| `test-worker.js` | проверка с подставными KV и сетью, настоящий `src/index.js` |
| `README.md` | зачем он есть и что замерено |

Два свойства, без которых кэш опаснее его отсутствия, и именно их проверяет
`test-worker.js`: он **никогда** не отдаёт данные тому, чей токен не
подтверждён, и **никогда** не переживает запись. Личные ответы (`/settings/get`)
кэшируются каждому свои — в ключ идёт отпечаток токена.

## Проверки

```sh
node apps-script/test-local.js     # бэкенд целиком, на эмуляторе таблицы
node worker/test-worker.js         # Worker с подставными KV и сетью
```

Браузерные наборы (Playwright) живут вне репозитория — это инструмент
разработки, а не часть системы.

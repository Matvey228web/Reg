# Как выкладывается система

Две половины выкладываются по-разному, и обе — без компьютера.

| Что | Куда | Чем |
|---|---|---|
| Приложение (`index.html`, `css/`, `js/`) | Cloudflare Pages | `wrangler pages deploy` |
| Бэкенд (`apps-script/Code.gs`) | Apps Script в таблице | `node apps-script/deploy.js push` |

Раньше вторая строка выглядела иначе: открыть редактор Apps Script на
компьютере, Ctrl+A, вставить 3600 строк, Deploy → Manage deployments → New
version. Это было единственное место, где система требовала человека за ПК.

---

## Бэкенд: что происходит при выкладке

`apps-script/deploy.js` делает мышиную последовательность запросами:

1. забирает содержимое проекта и **сверяет с репозиторием**;
2. кладёт новый `Code.gs`, не трогая остальные файлы проекта;
3. создаёт версию;
4. переводит на неё **существующее** развёртывание.

Четвёртый шаг — самое важное. Адрес `/exec` и есть идентификатор развёртывания
(`AKfycby…` в `js/config.js`). «New deployment» выдал бы новый адрес, и
приложение продолжило бы стучаться в старую версию. Поэтому обновляем
существующее развёртывание, и адрес не меняется никогда.

### Команды

```sh
node apps-script/deploy.js show          # что сейчас в проекте, ничего не меняет
node apps-script/deploy.js push          # сверить и выложить
node apps-script/deploy.js push --yes    # выложить, приняв различия
node apps-script/deploy.js verify        # спросить живой бэкенд про эндпоинты
```

### Почему `push` может отказаться

Если живой код отличается от репозитория, `push` показывает различия двумя
столбцами — «исчезнет из таблицы» и «появится в таблице» — и **останавливается**
с кодом 2.

Это не перестраховка. Так уже было: в редакторе руками поменяли название
категории на «Мониторы и трансляция», в репозитории осталось «Мониторы и
видеотракт». Выкладка без просмотра затёрла бы правку молча, и узнали бы об этом
через месяц по чужому вопросу «а куда делось название».

Увидели в столбце «исчезнет» что-то, чего не писали сами, — сначала перенесите
это в репозиторий, потом выкладывайте с `--yes`. Копия того, что лежало в
таблице до выкладки, остаётся в `remote-Code.gs` во временной папке — путь
печатается.

### Что нужно от человека

Один раз на аккаунт:

- `script.google.com` → шестерёнка (настройки) → включить **Google Apps Script
  API**. Без этого API отвечает отказом, даже с верным токеном.

Один раз на сессию Claude Code (контейнер временный, токен исчезает вместе с
ним):

1. Claude даёт короткую ссылку на страницу одобрения.
2. Открыть её с телефона, выбрать свою учётку, разрешить.
3. Браузер попробует открыть `localhost:8888` и покажет ошибку — так и должно
   быть, там никого нет. Скопировать адрес из строки браузера целиком (в нём
   `code=`) и прислать в чат.

Полную ссылку Google в чат кидать нельзя: её обрезает, и Google отвечает
«Missing required parameter: scope». Поэтому ссылка короткая, на своём домене.

### Права

Просим четыре, не больше:

| Право | Зачем |
|---|---|
| `script.projects` | читать и записывать содержимое проекта |
| `script.deployments` | создавать версии и переводить развёртывание |
| `script.webapp.deploy` | публикация веб-приложения |
| `drive.metadata.readonly` | найти проект, если потерялся Script ID |

Ни таблиц, ни почты, ни `cloud-platform`. Используется OAuth-клиент
официальной утилиты `clasp` — он опубликован Google, поэтому refresh-токен живёт
до отзыва. Свой клиент в статусе «Testing» выдавал бы токен на 7 дней
([документация Google](https://developers.google.com/identity/protocols/oauth2)),
и переподключаться пришлось бы каждую неделю.

Отозвать доступ в любой момент: `myaccount.google.com` → Безопасность →
Сторонние приложения → clasp.

### Чего конвейер не делает

- **Не ускоряет бэкенд.** Apps Script отвечает 5–8 секунд, это его потолок. От
  этого спасает Worker перед таблицей — он написан (`worker/`, `WORKER.md`) и
  пока не включён.
- **Не спасает от HTML вместо ответа.** Запрос к `/exec` уходит редиректом на
  `script.googleusercontent.com`, и когда второй запрос не доходит, в приложение
  приезжает страница Google вместо JSON. Это и есть «Некорректный ответ
  сервера», которое иногда видно в приложении. Лечится тем же Worker.
- **Не запускает `setupSheets`.** Если в схему добавились вкладки или колонки,
  функцию всё ещё надо один раз запустить из редактора. Появится нужда — вынесем
  в отдельную команду.

## Приложение: Cloudflare Pages

```sh
npx wrangler@latest pages deploy <папка> --project-name=mifs-rent \
  --branch=main --commit-dirty=true
```

Папка собирается из репозитория: `index.html`, `_headers`, `css/`, `js/`.
Привязки к Git у проекта нет намеренно — система ни от чего не зависит.

Про кэш: `?v=<версия>` в ссылках на свои файлы бессмысленно без `_headers`,
который запрещает кэшировать саму страницу. WebView Telegram держит страницу
жадно, и без этого правила человек видит старую версию при свежих файлах.
Версию в ссылках поднимаем каждой выкладкой.

Токен Cloudflare нужен с правами Pages → Edit. Он тоже живёт только в песочнице
сессии.

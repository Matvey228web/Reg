# apps-script — бэкенд

Вся логика системы одним файлом `Code.gs`, опубликованным как веб-приложение
Google Apps Script. Данные — в Google Sheets, привязанной к этому же проекту.

Своего сервера нет и не нужно: один Google-аккаунт держит и хранилище, и код.

| Файл | Что это |
|---|---|
| `Code.gs` | бэкенд целиком: роутер, эндпоинты, схема таблицы, импорт |
| `deploy.js` | выкладка через Apps Script API, без вставки руками |
| `test-local.js` | прогон логики без Google-аккаунта |

## Как устроен обмен

Apps Script даёт один адрес без путей, поэтому эндпоинт едет внутри тела:

```json
{ "endpoint": "/auth/login", "token": "…", "payload": { … } }
```

Ответ всегда JSON и всегда HTTP 200 — логический статус лежит внутри:

```json
{ "ok": false, "data": null, "error": "Сессия недействительна", "status": 401 }
```

Тип содержимого запроса — `text/plain`. Это не небрежность: на любом другом
браузер шлёт предварительный OPTIONS, которого `doPost` не обрабатывает, и
кросс-доменный запрос падает.

## Что стоит знать, прежде чем править

**Схема листов — в `SCHEMA`.** Новые колонки дописываются в конец, поэтому
писать строки надо по заголовкам листа, а не по порядку полей. После правки
схемы один раз запускается `setupSheets` — она добавит недостающее и не тронет
данные.

**Номера — текст, а не числа.** `010101` таблица норовит превратить в `10101`.
За это отвечает `TEXT_COLUMNS` и формат `@`; забыть — значит потерять ведущий
ноль и вместе с ним поиск по номеру.

**Номер вещи XXYYZZ — ссылка.** На него смотрят журнал выдач, дефекты и сверки.
Менять его можно только вместе с переписыванием этих ссылок — так устроен
`/model/move`.

**Ответ стоит 5–8 секунд.** Это потолок Apps Script. Поэтому дорогие операции
делаются одним запросом, а не десятком мелких.

## Проверки

```sh
node apps-script/test-local.js
```

Эмулятор нужных частей Apps Script API прогоняет `Code.gs` целиком: регистрация
и права, каталог и номера, выдача, приём с дефектом, перенос моделей, правка
номеров, сверка, отправка этикеток. Запускать после каждой правки.

## Выкладка

```sh
node apps-script/deploy.js show          # что сейчас в проекте
node apps-script/deploy.js push          # сверить и выложить
node apps-script/deploy.js verify        # спросить живой бэкенд
```

`push` сверяет живой код с репозиторием и без `--yes` останавливается, показав
различия. Это не перестраховка: правка, сделанная руками в редакторе, однажды
уже нашлась. Подробности — [`../docs/DEPLOY.md`](../docs/DEPLOY.md).

## Шаблон акта

`act-template.html` — акт колледжа, из которого убраны данные студента и на
место значений поставлены подстановки. Это HTML-выгрузка присланного
документа, а не нарисованный заново текст: у акта своя вёрстка — рамки,
шрифты, ширины столбцов, серая шапка таблицы, — и «примерно так же» для
документа о материальной ответственности не годится.

`deploy.js push` кладёт файл в проект Apps Script (тип HTML), код читает его
через `HtmlService.createHtmlOutputFromFile("act-template")` и превращает в
Google-документ загрузкой в Диск с mimeType документа. После создания
проверяется, что в документе нашлись все тринадцать подстановок; не нашлись —
черновик убирается в корзину, а ручка отвечает, каких именно не хватило.

Из шаблона убраны: ФИО, телефон, номер и дата чужого заказа, состав позиций
одной ячейкой и четырнадцать пустых строк «про запас». Столбец «МОДЕЛЬ»
переименован в «КОЛ-ВО»: отдельного поля модели у нас нет, а количество в
старом акте втискивали в название («OSTERRIG SIRIUS 50CM - 2x29000»).

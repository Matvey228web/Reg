# worker — кэш перед таблицей и приём заявок

**Включён и работает.** Адрес: `mifs-rent-api.odintsovmatvey08.workers.dev`.
Через него ходят оба: и сайт, и склад (`app/js/config.js`).

Замерено на живом воркере: отказ по кривой заявке — доли секунды, чтение из
кэша — 0,28–0,29 с против 6,6–9,1 с у таблицы, заявка принимается за 0,8 с.

Личные ответы — те, где есть «кто вы», сейчас это `/settings/get` — тоже
кэшируются, но каждому свой: в ключ идёт отпечаток токена. Иначе самый
медленный экран склада остался бы медленным, а сложить их в общий кэш нельзя —
складмен увидел бы панель администратора.

## Вторая работа: заявка с сайта

Apps Script отвечает 3,4–14 секунд вразнобой и раз в несколько запросов отдаёт
страницу ошибки Google вместо ответа (замерено). Прогрев не помогает. Студент
не должен в это упираться, поэтому заявку принимает Worker:

1. проверяет её на месте — номер, ФИО, телефон, число позиций, ловушка;
2. кладёт в KV;
3. **отвечает сразу**, за десятки миллисекунд;
4. доносит до таблицы в фоне, а `cron` раз в пять минут добирает то, что не
   доехало. Это же лечит случайные страницы ошибки.

Отказ по существу — «приём выключен» (403), «заявка кривая» (400), «номер в
таблице уже занят другим текстом» (409) — не повторяется бесконечно: заявка
перекладывается в `dead:` и остаётся видна. 409 раньше считался доставкой и
заявка удалялась — так терялась вторая заявка под тем же номером. Туда же, в
`dead:`, уходит запись очереди, которую не удалось даже разобрать: одна
испорченная запись не запирает cron для остальных.

Повторное нажатие с тем же текстом — не вторая заявка, а ответ «уже принято».
Тот же номер с **другим** текстом (студент поправил корзину, не перезагрузив
вкладку) — новая версия заявки: запись в очереди перезаписывается поверх, не
удаляется, чтобы между удалением и записью заявка не пропала.

Сайт ходит в Worker только двумя публичными эндпоинтами. Склад тоже ходит
через Worker, а не в таблицу напрямую: в `app/js/config.js` стоит адрес
Worker, адрес `/exec` знает только `UPSTREAM_URL` в `wrangler.toml`.

## Состояние очереди: `GET /health`

Отвечает без таблицы и без Telegram, только по KV:

```json
{ "ok": true, "queue": 0, "dead": 0, "oldest_dead_at": null }
```

`queue` — заявки, ещё не доехавшие до таблицы, `dead` — отложенные как
недоставляемые, `oldest_dead_at` — когда появилась самая старая из них. KV
недоступно — `503`. Для внешнего мониторинга; опрашивать **не чаще раза в
15 минут**: каждый вызов — две операции `list`, а их на бесплатном тарифе
около тысячи в сутки на всё, включая cron.

## Таблица не отвечает: 30 секунд

Apps Script отвечает 4–18 секунд. Если за 30 секунд ответа нет, его уже не
будет, и Worker обрывает запрос сам: «Таблица не ответила за 30 с, попробуйте
ещё раз» (`502`). Заявка с сайта при этом остаётся в очереди, cron доберёт её.

## Бережём записи в KV

На бесплатном тарифе Cloudflare записей в KV около тысячи в сутки на всё, а
чтений — в сто раз больше. Поэтому Worker сперва читает, потом пишет:

- `sess:<токен>` — отметка «токен уже подтверждён таблицей» — пишется, только
  если её ещё нет. Срок от этого не продлевается: через пять минут токен
  просто подтвердится заново.
- `chat:<id>` — чат, где видели бота, — переписывается, только если чат
  новый, переименован, сменил тип или запись старше недели (иначе истёк бы
  месячный срок хранения).

Без этого каждое сообщение в группе склада и каждый запрос склада стоили бы
записи, и лимит кончался бы к середине дня.

| Файл | Что это |
|---|---|
| `src/index.js` | сам Worker: кэш чтений, сброс на записи, проверка токена |
| `test-worker.js` | проверки логики кэша без Cloudflare |
| `wrangler.toml` | привязка KV и имя воркера |

Apps Script отвечает 5–8 секунд — это его потолок. Worker на Cloudflare встаёт
**перед** таблицей и отдаёт чтения из общего кэша за доли секунды.

Данные никуда не переезжают: истина в таблице, KV — только кэш. Протухает за
5 минут, сбрасывается на любой записи, в худшем случае пропускает запрос дальше.

**Выключается в любой момент** — приложение продолжит работать, просто медленно.

## Что это даёт

| | сейчас | с Worker |
|---|---|---|
| Каталог у первого за смену | 5–8 с | 5–8 с |
| Каталог у всех остальных | 5–8 с | доли секунды |
| Каталог после чистки браузера | 5–8 с | доли секунды |
| Кнопка «Обновить» | 5–8 с | 5–8 с (и это правильно: её жмут, когда не верят показанному) |
| Выдача, приём, заведение | 5–8 с | 5–8 с |

Записи быстрее не станут — ускоряется чтение, которого в смену в разы больше.

## Путь А. С телефона, через панель Cloudflare

1. **dash.cloudflare.com** → слева **Workers & Pages** → **Create** →
   **Start with Hello World!** → **Deploy**.
   Имя: `mifs-rent-api`.
2. Откройте созданный Worker → **Edit code**. Удалите всё, что там лежит, и
   вставьте содержимое файла `worker/src/index.js` целиком. **Deploy**.
3. Слева **Storage & Databases** → **KV** → **Create Instance**.
   Имя: `mifs-rent-cache`. **Create**.
4. Вернитесь в Worker → **Settings** → **Bindings** → **Add** → **KV namespace**:
   - Variable name: `CACHE`
   - KV namespace: `mifs-rent-cache`
5. Там же **Add** → **Environment variable**, дважды:
   - `UPSTREAM_URL` — адрес вашего Apps Script, тот самый, что стоит в
     `wrangler.toml` и заканчивается на `/exec`
   - `CACHE_ENABLED` — `1`
6. **Deploy**. Адрес Worker будет вида
   `https://mifs-rent-api.<ваш-поддомен>.workers.dev` — он показан на странице
   Worker сверху.

## Путь Б. С компьютера, через wrangler

```sh
cd worker
npx wrangler kv namespace create CACHE      # выведет id — впишите его в wrangler.toml
npx wrangler deploy
```

`UPSTREAM_URL` и `CACHE_ENABLED` уже лежат в `wrangler.toml`.

## Переключить приложение на Worker

В `js/config.js` заменить адрес Apps Script на адрес Worker:

```js
WEBHOOK_BASE_URL: "https://mifs-rent-api.<ваш-поддомен>.workers.dev",
```

и выложить фронтенд заново. **Пришлите мне адрес Worker — я переключу и выложу.**

Обратно возвращается так же: вписать прежний адрес `/exec`. Ничего больше менять
не нужно — формат запросов и ответов у Worker ровно тот же.

## Как проверить, что кэш работает

Каждый ответ Worker несёт заголовок `X-Mifs-Cache`:

- `miss` — ходил в таблицу и положил ответ в кэш;
- `hit` — отдал из кэша, таблицу не трогал;
- `bypass` — кэш к этому запросу не применяется (запись, настройки, «Обновить»);
- `error` — таблица не ответила.

Проще всего: откройте каталог дважды подряд. Второй раз должен нарисоваться
мгновенно.

## Что Worker никогда не делает

- **Не отдаёт данные по неподтверждённому токену.** Кэш достаётся только тому,
  чей токен уже проверял Apps Script. Подделанный токен получит отказ таблицы,
  а не каталог. Подтверждают токен только ручки, где таблица его проверяет:
  публичные (`/public/*`) отвечают «ок» на любой.
- **Не переживает запись.** Любая успешная запись — выдача, приём, заведение,
  правка настроек, доставленная заявка с сайта — сбрасывает кэш целиком, до
  ответа клиенту. Запись, на которую таблица не ответила (502), тоже: исход
  неизвестен. Неудачная по существу (например, «предмет уже выдан») не
  сбрасывает: сбрасывать нечего. Оговорка KV: между точками присутствия
  Cloudflare новое поколение расходится до ~60 секунд.
- **Не кладёт в общий кэш личное.** Настройки (в них «кто вы») и список
  сотрудников (только админу) кэшируются каждому под своим ключом.
- **Не отдаёт токен бота.** Токен живёт в двух серверных хранилищах —
  Script Properties (таблица) и Worker Secrets (вебхук). В репозиторий и в
  браузер он не попадает.

Отозванный токен (выход, смена PIN, увольнение) живёт в кэше не дольше пяти
минут — ради этого срок и короткий.

---

## Если что-то пошло не так

Кэш выключается **без выкладки**: Worker → **Settings** → **Variables** →
`CACHE_ENABLED` = `0` → **Deploy**. Все запросы пойдут напрямую в таблицу.

Если и этого мало — верните в `js/config.js` прежний адрес `/exec`.

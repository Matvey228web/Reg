# SETUP: настройка бэкенда и деплой Mifs Rent

Этот репозиторий содержит только фронтенд — Telegram Mini App (статические HTML/CSS/JS файлы, без сборки). Хранение данных и бизнес-логика находятся вне репозитория, в **Google Sheets** (таблица с данными) + **Google Apps Script** (один файл кода, который выполняет всю логику и отдаёт её как веб-приложение). Всё это — один Google-аккаунт, никаких дополнительных сервисов.

Пока бэкенд не настроен, приложение можно полноценно использовать в демо-режиме — см. раздел «Mock-режим» в README.md.

---

## 1. Таблица в Google Sheets

Откройте **sheets.google.com** → «Создать пустую таблицу» → назовите её, например, «Mifs Rent Warehouse».

Всё. Больше здесь ничего делать не нужно: вкладки и заголовки колонок создаст сам скрипт на следующем шаге (§2, пункт 5). Вручную ничего вписывать не надо — так исключаются опечатки в названиях, из-за которых бэкенд молча перестал бы находить данные.

Для справки, какая структура получится (проверять не обязательно):

| Вкладка | Колонки |
|---|---|
| Equipment | `item_id, name, category, serial_number, inventory_number, status, condition_notes, created_at, current_transaction_id` |
| Staff | `staff_id, full_name, login, pin_hash, telegram_id, role, active, session_token, token_issued_at` |
| Clients | `client_id, client_name, project_name, phone, notes, created_at` |
| Transactions | `transaction_id, item_id, client_id, staff_out, staff_in, checked_out_at, expected_return_at, checked_in_at, status, notes` |
| Defects | `defect_id, item_id, reported_by, related_transaction_id, description, severity, status, reported_at, resolved_at, resolution_notes` |
| Meta | `key, value` (служебная — внутренние счётчики ID) |

Строки данных (оборудование, сотрудники, клиенты) добавляются потом прямо из приложения. После создания структуры вкладки **Staff** и **Meta** останутся пустыми — это нормально: первый администратор заводится из самого приложения (см. §4).

## 2. Бэкенд (Google Apps Script)

1. В открытой таблице: меню **Расширения → Apps Script** (Extensions → Apps Script).
2. Откроется редактор кода с файлом `Code.gs` — сотрите в нём всё содержимое.
3. Откройте в репозитории файл `apps-script/Code.gs`, скопируйте его **целиком** и вставьте в редактор Apps Script.
4. Сохраните (иконка дискеты или Ctrl+S).
5. **Создайте структуру таблицы**: вверху редактора, рядом с кнопкой «Выполнить» (Run), выберите в списке функций `setupEverything` и нажмите **Выполнить**. Она создаст все вкладки и, если задан `IMPORT_SOURCE_ID`, сразу перенесёт туда существующую инвентаризацию (см. §8). Если импорт не нужен — выберите `setupSheets`, она только создаёт вкладки.
   - При первом запуске Google попросит разрешение на доступ к вашей таблице. Появится предупреждение вида «Google не проверило это приложение» — **это ожидаемо**, потому что скрипт написан вами, а не опубликован в магазине приложений. Нажмите «Дополнительные настройки» (Advanced) → «Перейти к проекту … (небезопасно)» → «Разрешить».
   - После выполнения вернитесь во вкладку с таблицей — там появятся 6 вкладок с заголовками.
   - Функцию можно запускать повторно сколько угодно раз: существующие данные не затираются.
6. Нажмите **Развернуть → Новое развёртывание** (Deploy → New deployment).
7. Рядом с «Выберите тип» нажмите на шестерёнку → выберите **Веб-приложение** (Web app).
8. Настройки развёртывания:
   - **Запуск от имени** (Execute as): Me / от вашего имени
   - **У кого есть доступ** (Who has access): **Anyone / Все** — именно «Все», а не «Все, у кого есть аккаунт Google», иначе приложение получит отказ
9. Нажмите **Развернуть**.
10. Скопируйте появившийся **URL веб-приложения** — он заканчивается на `/exec`. Это и есть адрес вашего бэкенда.
11. **Проверьте сразу**: откройте этот URL в новой вкладке браузера. Должна появиться строка «Mifs Rent backend работает. Запросы принимаются через POST.» Если так — бэкенд поднят корректно.

При каждом последующем изменении `Code.gs` нужно заново нажать **Развернуть → Управление развёртываниями → Изменить (карандаш) → Развернуть**, чтобы правки применились — простое сохранение файла в редакторе на уже опубликованную версию не влияет.

### Как это устроено (для справки, менять не нужно)

Apps Script даёт только один URL без отдельных путей вида `/auth/login` — поэтому приложение отправляет одним запросом JSON вида `{ "endpoint": "/auth/login", "token": "...", "payload": {...} }`, а `Code.gs` сам разбирает, какой это эндпоинт, и возвращает `{ "ok": true/false, "data": ..., "error": ..., "status": ... }`.

## 3. Бот в Telegram (BotFather)

1. Откройте `@BotFather` → `/newbot`, задайте имя и username бота.
2. После деплоя фронтенда (см. §6) получите его HTTPS-URL.
3. `/setmenubutton` → выберите вашего бота → укажите текст кнопки (например, «Открыть склад») и вставьте HTTPS-URL приложения (`index.html`).
4. Дополнительно можно настроить `/setdescription`, `/setuserpic`.

Отдельный код бота не требуется: кнопка меню сразу открывает статическую страницу как Telegram Mini App.

## 4. Регистрация сотрудников — прямо в приложении, без ручных действий

Ничего вручную считать или вписывать в таблицу не нужно — PIN хэшируется на сервере автоматически.

**Первый администратор** (когда таблица Staff ещё пустая):
1. Откройте приложение (через бота или напрямую по ссылке).
2. На экране входа нажмите «Нет сотрудников в системе? Создать первого администратора».
3. Введите своё имя, придумайте логин и PIN, нажмите «Создать администратора и войти» — вы сразу окажетесь внутри приложения под ролью «Администратор».

Это работает только один раз — как только в Staff появляется хотя бы одна запись, повторная попытка создать администратора без входа будет отклонена («Сотрудники уже есть, обратитесь к администратору»).

**Остальные сотрудники** — уже под администратором:
1. На главном экране откройте «Сотрудники» (карточка видна только администратору).
2. «+ Добавить сотрудника» → имя, логин, PIN, роль (Сотрудник склада / Администратор) → «Добавить».
3. Сообщите новому сотруднику логин и PIN — больше ничего устанавливать не нужно, достаточно открыть бота в Telegram.

На этом же экране можно отключить сотрудника (кнопка «Отключить») — доступ отзывается, история его выдач/действий сохраняется.

## 5. Схема ID / QR-кодов

Формат: `MIFS-<КОД_КАТЕГОРИИ>-<порядковый номер, 3 цифры>`, например `MIFS-CAM-014`. Коды категорий: `CAM` (камера), `LEN` (объектив), `LGT` (свет), `AUD` (звук), `GRP` (грип), `OTH` (другое). ID генерируется внутри `Code.gs` при создании оборудования (счётчики хранятся на вкладке `Meta`, под блокировкой — чтобы два одновременных добавления с разных телефонов не создали одинаковый ID). QR-код кодирует только сырую строку `item_id`, без URL.

## 6. Деплой фронтенда (без GitHub)

Telegram требует HTTPS-адрес для Mini App. Ничего не должно быть привязано к GitHub-аккаунту — используйте один из вариантов ручной/CLI-загрузки статики:

### Вариант А — Netlify Drop (проще всего)
1. Откройте https://app.netlify.com/drop
2. Перетащите в браузер папку репозитория (все файлы: `index.html`, `css/`, `js/`, и т.д.)
3. Получите готовый HTTPS-URL — используйте его в BotFather (§3)
4. Для последующих обновлений: перетащите папку заново, или установите Netlify CLI и деплойте командой `netlify deploy --prod --dir=.` — тоже без подключения Git-репозитория

### Вариант Б — Cloudflare Pages, прямая загрузка
1. Установите Wrangler CLI: `npm install -g wrangler`
2. В папке проекта: `wrangler pages deploy .`
3. Следуйте инструкциям CLI (создание проекта, без привязки к Git)
4. Получите HTTPS-URL проекта

В обоих случаях исходный код может продолжать храниться в этом Git-репозитории — это просто хранилище кода. Сам деплой/обновление сайта делается вручную загрузкой файлов, никакая GitHub-интеграция (Pages, Actions, вебхуки) не используется.

## 7. Переключение с mock-режима на реальный бэкенд

В `js/config.js`:
```js
WEBHOOK_BASE_URL: "https://script.google.com/macros/s/ВАШ_ID/exec",
MOCK_MODE: false,
```

После этого повторно задеплойте статику (см. §6) и проверьте по цепочке: создание первого администратора (§4) → вход → добавление сотрудника → каталог (создание предмета + QR) → скан (выдача/приём) → дефекты → история.

### Если что-то не работает

**Ошибка «Не найдена вкладка …»** — структура таблицы не создана или создана частично. Откройте редактор Apps Script и запустите функцию `setupSheets` ещё раз (см. §2, пункт 5), это безопасно и не затирает данные.

**Запросы не проходят (белый экран, «Нет связи с сервером»)** — это единственное место, которое не проверено на живом Google-аккаунте (логика бэкенда покрыта локальными тестами, см. ниже, но сам факт сетевого доступа из браузера к `/exec` проверяется только вживую). Попробуйте по порядку:
1. Убедитесь, что в настройках развёртывания стоит «У кого есть доступ: Все» (Anyone), а не «Все, у кого есть аккаунт Google».
2. Откройте URL `/exec` напрямую в браузере — должно показать текст «Mifs Rent backend работает…». Если там ошибка — проблема в деплое Apps Script, а не во фронтенде.
3. Проверьте в `js/config.js`, что `WEBHOOK_BASE_URL` скопирован полностью, включая `/exec` на конце, без лишних пробелов и кавычек.
4. Если правили `Code.gs` после первого деплоя — заново нажмите «Развернуть → Управление развёртываниями → Изменить → Развернуть».

**Вход не проходит, хотя логин и PIN верные** — проверьте на вкладке `Staff`, что в строке сотрудника в колонке `active` стоит `TRUE`, а не пусто.

## 8. Перенос существующей инвентаризации

Если оборудование уже учтено в другой Google-таблице, его не нужно вбивать руками — функция `importInventory()` перенесёт всё в каталог.

1. В `Code.gs` вверху найдите строку `var IMPORT_SOURCE_ID = "..."` и впишите туда ID исходной таблицы. ID берётся из её адреса: `docs.google.com/spreadsheets/d/`**`ЭТОТ_КУСОК`**`/edit`.
2. Запустите `setupEverything` (или отдельно `importInventory`, если вкладки уже созданы).

Что импорт делает с «живыми» данными склада, где формат вкладок обычно неровный:

- **Категория** определяется по типу и названию: камеры → `CAM`, объективы → `LEN`, свет → `LGT`, звук → `AUD`, штативы и обвес → `GRP`, остальное → `OTH`.
- **Статус** — из колонки «Состояние»: «Работает» и пустые → Доступно; «Не работает», «Ремонт», «Сломан», «Разбит» → В ремонте; «Потерян» → Списано. Произвольный текст («царапины на матрице») не теряется — позиция остаётся доступной, а текст уходит в заметки.
- **Строки-заголовки групп** («Камеры», «Объективы») пропускаются — и объединённые ячейки, и строки, где одно значение продублировано по всем колонкам.
- **Вкладки без заголовков колонок** разбираются по позиции — название берётся из первой колонки.
- **Дубли** склеиваются только по настоящему заводскому номеру. Мусорные значения вроде `?`, `1`, `2` серийниками не считаются: иначе склеилось бы не связанное оборудование.
- **Одинаковые названия не склеиваются.** На складе десятки физически разных единиц с одним названием и без серийника (чайнаболлы, октобоксы, радиосистемы) — каждая остаётся отдельной позицией со своим QR.
- **Повторный запуск безопасен**: в заметках сохраняется метка «Импорт: вкладка#строка», уже перенесённые строки пропускаются.

После импорта `IMPORT_SOURCE_ID` можно очистить — он больше не нужен.

## 9. Локальная проверка бэкенда (для разработки)

Логику `Code.gs` можно прогнать целиком без Google-аккаунта — есть эмулятор нужных частей Apps Script API:

```
node apps-script/test-local.js
```

Скрипт создаёт структуру таблицы в памяти и проходит полный сценарий: регистрация первого администратора → вход → добавление сотрудника → создание оборудования и генерация ID → выдача → приём с дефектом → закрытие дефекта → истории, фильтры, права доступа. Полезно запускать после любых правок `Code.gs` перед тем, как заново деплоить его в Google.

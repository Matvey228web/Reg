# SETUP: настройка с нуля

В репозитории только фронтенд — статические HTML/CSS/JS без сборки. Данные и
логика живут в **Google Sheets** (таблица) и **Google Apps Script** (`Code.gs`,
опубликован как веб-приложение). Один Google-аккаунт, больше ничего.

Повседневная работа — в `MANUAL.md`, выкладка обновлений — в `DEPLOY.md`, бот —
в `BOT.md`. Пока бэкенда нет, приложение работает в демо-режиме (`README.md`).

---

## 1. Таблица

**sheets.google.com** → создать пустую таблицу, назвать.

Больше здесь делать нечего: вкладки и заголовки создаст скрипт на следующем
шаге. Вручную вписывать ничего не надо — опечатка в названии колонки приведёт к
тому, что бэкенд молча перестанет находить данные.

Получится четырнадцать вкладок; их состав описан в `MANUAL.md`, §5.

---

## 2. Бэкенд

1. В таблице: **Расширения → Apps Script**.
2. Стереть содержимое `Code.gs`, вставить целиком `apps-script/Code.gs` из
   репозитория, сохранить.
3. Выбрать вверху функцию **`setupEverything`** → **Выполнить**. Она создаёт
   вкладки и, если задан источник импорта, сразу переносит существующую
   инвентаризацию (§6). Только вкладки — `setupSheets`.
   - Google попросит разрешение и покажет «Google не проверило это приложение»:
     Дополнительные настройки → Перейти к проекту → Разрешить.
   - Запускать можно сколько угодно раз, данные не затираются.
4. **Развернуть → Новое развёртывание** → шестерёнка → **Веб-приложение**.
5. Запуск от имени: **Me**. Доступ: **Все (Anyone)** — именно «Все», не «Все,
   у кого есть аккаунт Google».
6. Скопировать URL, он заканчивается на `/exec`.
7. Открыть его в браузере: должно ответить «Mifs Rent backend работает.
   Запросы принимаются через POST.»

Дальше `Code.gs` обновляется командой из `DEPLOY.md` — вставлять руками больше
не нужно.

Apps Script даёт один URL без путей, поэтому приложение шлёт
`{ "endpoint": "/auth/login", "token": …, "payload": … }`, а `Code.gs` сам
разбирает, какой это эндпоинт.

## 3. Бот

1. `@BotFather` → `/newbot`, задать имя и username.
2. После выкладки фронтенда (§5) взять его HTTPS-адрес.
3. `/setmenubutton` → выбрать бота → текст кнопки и адрес приложения.

Отдельного кода бота не нужно. Уведомления и отправка этикеток — в `BOT.md`.

---

## 4. Первый вход

PIN хэшируется на сервере, вручную в таблицу вписывать нечего.

**Первый администратор** (пока `Staff` пуста): на экране входа — «Нет
сотрудников в системе? Создать первого администратора» → имя, логин, PIN.

Работает один раз: как только в `Staff` появилась запись, эта дверь
закрывается.

**Остальные** — главный администратор заводит их на экране «Сотрудники».

## 5. Выкладка фронтенда

Telegram требует HTTPS. Проект живёт на Cloudflare Pages, без привязки к Git:

```sh
npx wrangler@latest pages deploy <папка> --project-name=mifs-rent \
  --branch=main --commit-dirty=true
```

Подробности и правила кэша — в `DEPLOY.md`.

Переключение с демо-режима на живой бэкенд — в `js/config.js`:

```js
WEBHOOK_BASE_URL: "https://script.google.com/macros/s/ВАШ_ID/exec",
MOCK_MODE: false,
```

## 6. Схема номеров

Номер вещи — шесть цифр **XXYYZZ**: категория, модель внутри категории,
экземпляр. `010201` — камера, вторая модель, первый экземпляр.

| Код | Номер | Категория | | Код | Номер | Категория |
|---|---|---|---|---|---|---|
| CAM | 01 | Камеры | | SUP | 08 | Штативы и поддержка |
| LEN | 02 | Объективы | | MOD | 09 | Модификаторы света |
| LGT | 03 | Осветители | | MON | 10 | Мониторы и трансляция |
| AUD | 04 | Звук | | RIG | 11 | Обвес камеры |
| GRP | 05 | Грип | | FLT | 12 | Фильтры |
| OTH | 06 | Другое | | PWR | 13 | Питание |
| CNS | 07 | Расходники | | MED | 14 | Носители |

`GRP` и `CNS` считаются количеством, остальные поштучно. Категории заводятся и
переименовываются в приложении; номер у категории с техникой не меняется — он
напечатан на этикетках.

Справочник моделей — вкладка `Models`. Названия сравниваются нормализованно:
`GODOX SL 300 R` и `Godox SL300 R` — одна модель. Кириллические двойники
латинских букв тоже учитываются.

Границы: 99 моделей на категорию, 99 экземпляров на модель. Сейчас занято
максимум 43 и 59. Номера не переиспользуются: списанная позиция не отдаёт свой
номер следующей. QR кодирует только номер, без URL.

## 7. Перенос существующей инвентаризации

1. Настройки → «Исходная таблица»: идентификатор из её адреса
   (`docs.google.com/spreadsheets/d/`**`ЭТОТ_КУСОК`**`/edit`).
2. Запустить `setupEverything` (или отдельно `importInventory`).

Обе функции сами дописывают недостающие вкладки и колонки.

`reimportInventory` соберёт каталог заново с нуля — но откажется работать на
складе, где выдачи уже начались.

Что импорт делает с неровными данными:

- **Категория** — по правилам листа `ImportRules`: название, колонка «Тип», имя
  вкладки. Ничего не совпало — `OTH`.
- **Статус** — из колонки «Состояние». Произвольный текст («царапины на
  матрице») уходит в заметки, позиция остаётся доступной.
- **Строки-заголовки групп** пропускаются.
- **Вкладки без заголовков** разбираются по позиции колонок.
- **Дубли** склеиваются только по настоящему заводскому номеру; `?`, `1`, `2`
  серийниками не считаются. Одинаковые названия не склеиваются — на складе
  десятки разных вещей с одним названием и без серийника.
- **Повторный запуск безопасен**: в заметках остаётся метка «Импорт:
  вкладка#строка».

### `ImportMap` и `ImportRules`

Оба листа создаются с умолчаниями и правятся прямо в таблице, без правки кода.
Повторный `setupSheets` заполненный лист не трогает.

**`ImportMap` — как называются колонки.** Синонимы проверяются слева направо,
первый непустой выигрывает.

| field | aliases |
|---|---|
| `name` | `Наименование, Название, Оборудование, col0, Тип` |
| `serial_number` | `Заводской номер, Серийный номер, Serial, S/N` |
| `inventory_number` | `Инвентарный номер, Инв. номер, Инв номер` |
| `type` | `Тип, Категория` |
| `status` | `Состояние, Статус, ЗВУК:col2` |
| `kit` | `Комплектация, Комплектация 13.04 наличие` |
| `notes` | `Примечания, Комментарий` |
| `storage` | `Хранение` |

Две особые формы: `col0` — колонка по счёту, для вкладок без заголовков;
`ЗВУК:col2` — то же, но только на вкладке с этим именем.

«БЕЗ НАЗВАНИЯ: N» в отчёте — колонка называется иначе, допишите её в `aliases`
строки `name`.

**`ImportRules` — что в какую категорию.** Правила проверяются сверху вниз,
первое совпавшее выигрывает, поэтому частные стоят выше общих: «стойка» в `GRP`
выше правил света, и «Стойка Godox» — грип.

| колонка | что значит |
|---|---|
| `category` | код категории: `CAM`, `LEN`, `LGT`, … |
| `match` | `name` — в названии, `type` — в колонке «Тип», `tab` — имя вкладки |
| `keywords` | слова через запятую, регистр не важен |

## 8. Если что-то не работает

**«Не найдена вкладка …»** — запустите `setupSheets` ещё раз, это безопасно.

**Запросы не проходят.** По порядку: доступ у развёртывания «Все (Anyone)»;
`/exec` открывается в браузере и отвечает текстом; `WEBHOOK_BASE_URL` скопирован
целиком вместе с `/exec`; после правки `Code.gs` выложена новая версия.

**Вход не проходит при верном PIN** — на вкладке `Staff` в колонке `active`
должно стоять `TRUE`.

## 9. Локальная проверка

```sh
node apps-script/test-local.js
```

Эмулятор нужных частей Apps Script API прогоняет `Code.gs` целиком без
Google-аккаунта: регистрация, вход, каталог и номера, выдача, приём с дефектом,
перенос моделей, правка номеров, права доступа. Запускать после любой правки
`Code.gs`.
